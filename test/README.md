# Adversarial Foundry coverage

These tests extend the existing integration suite using the approved workflow and frozen economics in `SPEC.md`. All dependencies are already vendored. No RPC, fork, FFI, environment mutation, or generated file in `test/scratch/` is required.

| File | Properties and failure paths |
| --- | --- |
| `BatchSwapAtomicity.t.sol` | Two real swaps within one PoolManager unlock (token A → ETH → token B, and same-pool round trips). Checks each leg's 1% fee from actual ETH movement, separate creator credits, no external ETH bridge payment, failure/retry of escrow delivery, and per-leg odd-wei rounding. Second-leg partial fills, an ungraduated second pool, slippage rejection after both swaps, and insufficient allowance during final settlement must undo both legs' prices, token movements and delivered/deferred fees. Successful retries verify that reverted unlocks leave no transient debt or stuck lock. |
| `BatchSwapInvariant.t.sol` | 128 random sequences of depth 64 over three actors, both route directions, same-pool round trips, crown changes, fee delivery outages, permissionless retries, withdrawals and reverted batches. An independent ledger checks each creator and captured king, actual ETH custody, token supply conservation, zero unsettled currency deltas, and unchanged full-range factory LP. A deterministic sequence covers both deferred legs, old/new king buckets and failed retries. |
| `CallbackAtomicity.t.sol` | Rejected over-cap refunds undo token delivery and direct/deferred fee accounting; exact-cap retry for a refund-rejecting contract; refund callbacks cannot reenter buys or sells; worker payout callbacks may donate without mixing overlapping epoch budgets and cannot reenter epoch creation; failed worker funding rolls back both first and subsequent crowns. |
| `ProjectDeployment.t.sol` | Constructor-only CREATE2 deployment through a separate service factory; hook salt and 0x08cc address checks, init-code size limit, protocol supply unchanged after every constructor, explicit updater/genesis roles independent of deployer, second launch and full-range graduation, atomic failure with mismatched dependencies followed by retry, and the offline `script/MineHookSalt.s.sol` evidence deploying the hook while unmined salts fail. |
| `TokenInvariant.t.sol` | Independent holder/allowance ledgers for both fixed-supply tokens; random transfers, approvals, delegated spending, overspending and invalid recipients; full supply, one wei, zero, maximum approval and failed-spend rollback. |
| `AccountingInvariant.t.sol` | Independent worker deposit/payment ledger, overlapping Merkle epochs, claims, expiry recycling and updater rotation; fee entitlements across crowns, original beneficiaries, odd wei, failed withdrawals and recorder authorization. |
| `CurveInvariant.t.sol` | Multi-actor buy/sell sequences, reserve-product monotonicity, exact ETH/token conservation, plain ETH transfers refused and token donations excluded from reserves, deferred fee retries, captured beneficiaries, irreversible readiness at 4.2 ETH, graduation finality and failed cap-refund rollback. |
| `HookInvariant.t.sol` | Two graduated pools using the real vendored Uniswap v4 PoolManager (the second with rejected pre-graduation saturation attempts and a real foreign position added after graduation), all four swap modes, fees derived from actual ETH movement, failed delivery/retry, crown changes, withdrawals, supply conservation and unchanged factory-owned LP positions. |
| `GraduationLiquidity.t.sol` | Proofs for the hook's pre-graduation liquidity gate: tick-cap grief on either boundary, repeated attempts across many ticks and around the price, attempts while the curve is full, all reverting `LiquidityClosed` and leaving a full-range lock; liquidity opening after graduation with removable own positions; unbound pools staying closed; the defense-in-depth boundary scan and its rollback; fuzzed threshold sells of any size. |
| `LaunchResalt.t.sol` | Bounded salt retry for poisoned predicted pools: skip to the next salt, canonical preinitialization kept, successive front-running, fuzzed poison depth, genesis re-salting inside the factory constructor, `predictLaunchToken` agreement with actual creates; and when all 16 candidates are poisoned, realignment of the first candidate (events, no value moved, siblings untouched, graduation afterwards), the reviewer's all-16-genesis-candidates proof against the future factory address, realignment from both extreme prices, and a fresh user salt still escaping. |
| `GenesisPoison.t.sol` | The judge's genesis-poison scenario end to end: a service-style CREATE2 deployer announces the factory address, all 16 genesis candidate pools are initialized at a foreign price before the deploy (fixed, and fuzzed on both sides of canonical down to the v4 extremes), and the factory still deploys at the predicted address with genesis on candidate 0 at the canonical price, zero liquidity, `PoolRealigned`/`LaunchPoolRealigned` emitted, no value moved, siblings untouched, then graduates full range and charges the 1% fee. Canonical preinitialization accepted without realignment; partial poison re-salts inside the constructor. Failure paths through a direct PoolManager probe: strangers cannot realign, re-initialize, swap or add liquidity; the factory cannot realign an unbound sibling; a realignment that leaves a foreign price aborts the deploy with the CREATE2 address still free and the same salt retries; later launches keep the bounded re-salt. |
| `PoolRealign.t.sol` | `PvPadHook.realignPool` permissions on the real PoolManager: strangers, the creator, unbound pools, already-canonical pools and graduated pools (liquidity present) are all refused and prices untouched; `unlockCallback` accepts only the PoolManager during a realignment; a realigned pool stays closed before graduation, graduates at the realigned tick and charges the 1% fee on real swaps afterwards. |
| `HookSecurity.t.sol` | Fault-injected hook unit tests: 0x08cc flags and rejected legacy 0x00cc addresses, `beforeAddLiquidity` admitting only the bound factory until graduation, unbound pools and direct calls rejected, swap fee math, deferred delivery and retries. |
| `FactoryAdversarial.t.sol` | Invalid configuration/fees/metadata, missing or unfunded launches, independent launches with repeated salts, complete creation rollback followed by successful retry with identical inputs, and stray ETH refused by both the factory and the curve while the graduation sweep still lands. |
| `WorkerAdversarial.t.sol` | Cross-epoch proof replay, overallocated-root budget isolation, window boundaries, superseded updaters, callback accounting and reentrancy, overlapping creator/king roles and explicit fee validation. |
| `SystemLifecycleInvariant.t.sol` | Whole-deployment campaign on the real factory, PoolManager and shared hook: launches created on the fly (up to four), curve buys/sells with quote-equals-execution and exact one-percent fee checks, fills, permissionless graduation, all four swap modes on graduated pools, crown changes, escrow outages with deferred fees, flush/retry, withdrawals, pre-crown fee assignment, ETH and token donations to curves, worker funding, and a probe of every privileged or malformed entry point. Invariants: every launch token is held by a known party; curve custody equals reserves plus retained fees plus donations; graduation is final with the locked full-range position unchanged and ungraduated pools empty at the canonical price; every fee wei is delivered, deferred or withdrawn exactly once with the 50/50 split (odd wei to the creator, pre-crown share to the first king) checked per payee against an independent ledger; worker pot and claim price follow the frozen economics. |
| `CurveMathProperties.t.sol` | Stateless curve arithmetic from random prior fills: quotes equal execution for buys and sells; `maxBuyInput` is the smallest gross input that fills the curve (one wei less lands exactly one wei short); every input below the cap stays strictly below the threshold; excess over the cap is refunded to the sender, not the recipient; fee-free dust (1–99 wei) and trades of any size cannot be round-tripped at a profit; later buyers never get a better price and quotes are monotone; a holder can always exit the whole circulating supply leaving at most one wei of rounding; selling more than was ever bought is rejected even with a synthetic balance; slippage, deadline, zero-address and zero-amount guards leave state untouched; a failed token pull rolls the sale back; graduation seeds the pool at the curve's terminal price with wei-level dust. One-wei, 99-wei, 100-wei and exact-cap edges are pinned as unit tests. |

The recovery revision adds 128 fuzz runs over poisoned prices on both sides of the canonical price and arbitrary user salts. `LaunchResalt.t.sol` also injects five failures: a missing manager callback, nonzero swap delta, zero delta without a price update, a hook that returns without restoring the price, and worker funding failure after successful realignment. Each case checks complete launch rollback (including the original poisoned price, bindings, recorder permission and creator payment), then retries identical inputs successfully. These mocks exercise defensive checks; they do not imply the trusted PoolManager naturally returns those results.

`SystemLifecycleInvariant.t.sol` now creates launches after poisoning some or all 16 candidates, including while existing pools and the shared hook hold value. Its original conservation and graduation invariants apply to the recovered launches throughout later random calls. A deterministic sequence covers recovery in both price directions with existing locked liquidity and deferred fees. Plain ETH donation attempts now assert rejection and unchanged sender/curve balances, matching the source revision that removed the curve's `receive()`.

Invariant handlers select bounded inputs and several actors, track independent expected balances or entitlements, and check them after each call. Expected failures assert their revert reasons; unexpected handler reverts fail the campaign. Deterministic sequences also exercise successful claims, recycling, deferred delivery and graduation so the important transitions do not rely solely on random selection.

Run counts live in Solidity inline configuration: 256 sequences of depth 64 for tokens, 128 of depth 64 for the worker/escrow/curve campaigns, 128 of depth 48 for the real-pool campaign, and 96 of depth 48 for the whole-deployment lifecycle campaign. Worker adversarial fuzz properties and the curve arithmetic properties use 512 runs.

The lifecycle handler measures fees from ETH that actually moved (trader paid minus reserve or pool growth) and decides whether a fee was deferred from where the ETH ended up (curve or hook custody versus escrow), then checks the contracts' own counters against that. Escrow outages are injected with `vm.mockCallRevert` on the two delivery entry points only; the authorization probe uses an entry point that is never mocked. No new defect was found by these campaigns; behaviours that are by design but worth knowing (tokens sent to a curve outside a trade stay there forever, graduation rounding dust stays in the factory) are asserted as stated in the source comments rather than reported. Plain ETH transfers to curves are rejected.

The batch router in `helpers/BatchSwapFixture.sol` is test scaffolding, not a production router. It executes both real PoolManager swaps before settling the net token deltas; the intermediate ETH never leaves flash accounting. Per-leg observations measure the manager's ETH balance decrease during each swap, then the tests independently check the one-percent rule and the payees' entitlements. These tests use native settlement, two graduated pools and the existing plain ERC-20 tokens; they do not claim coverage of ERC-6909 claim settlement or arbitrary third-party token behavior. The four batch fuzz properties each use 512 runs. Fee delivery failures are explicitly injected, as in the existing hook campaigns.

The curve invariant uses a minimal factory fixture to control escrow-recorder availability and exercise the authorized reserve sweep. The real-pool tests exercise actual factory deployment and locked graduation. Hook delivery failures and factory worker-payment failures are explicitly injected with Foundry mocks; this tests rollback and deferred accounting without claiming those failures arise naturally. Assertions of exact asset equality cover the holders and funding paths driven by each handler; unsolicited forced ETH is outside these campaigns.

The graduation regressions keep a fully funded curve unswept, then attempt one-unit, 99-wei-output dust and full-holder-balance sells, buys, donations and deferred fee retries before graduation. Two 256-run fuzz tests check both sell overloads and rollback at capacity, on the minimal fixture and on the real factory. The hook campaign attempts to saturate both extreme tick pairs with real v4 deposits before graduating its second launch (every attempt reverts `LiquidityClosed` as a v4 `WrappedError`), adds a real foreign position after graduation, snapshots the full-range bounds, and checks that later swaps and unauthorized removal attempts cannot change the locked position.

Normal verification uses `forge build` and `forge test`. To keep generated artifacts inside the disposable assignment directory and verify without network access:

```sh
forge build --offline --out test/scratch/out --cache-path test/scratch/cache
forge test --offline --out test/scratch/out --cache-path test/scratch/cache
```

Delete `test/scratch/` freely: no submitted test imports from it.
